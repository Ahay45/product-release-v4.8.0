UI Click Tracking — Product Usage Dashboard

Every number on this page comes from the live chatmary tracking store. Nothing is sampled, modelled, or estimated.

Headline

What to do about it

Ranked by expected return. Each names the figure it came from, so it can be argued with.

Active account base

Every registered team, narrowed stage by stage. Sourced from auth/teams (all enumerated, not sampled) and payments/subscriptions.

The base is mostly empty signups. Under 1% of registered teams have ever connected a channel, so “% of all accounts” is a misleading denominator for anything. Judge feature usage against the provisioned population, not the registered one.

Churn

Subscription state per team, and the usage signal that precedes a cancellation.

Subscriptions lapsing per month
What this is and isn't. A team counts as lapsed when its latest dated subscription renewal is in the past — that is a real, dated event, and the only genuine time series anywhere in this data. The click store has no per-day breakdown, so usage cannot be trended alongside it. Rows without a renewal date are one-off purchases and are excluded from both sides.

Journey depth

How much of the product each active team actually reaches, measured as the number of distinct areas it touched in the window.

This is breadth, not a path. It says how far a team spread across the product, not the order it moved in — the tracking store keeps no per-event sequence, and the endpoint meant to supply one returns impossible numbers (see Data quality). A real step-by-step journey needs an ordered event read that does not exist yet.

Kill list — review queue

Features touched by three teams or fewer in the window, carrying maintenance and test cost against near-zero measured use.

Do not action this list directly. Low clicks can mean poor discoverability rather than low value, and the window is 7 days — anything used monthly (exports, billing changes, seasonal campaigns) looks dead here. Auth, billing, admin and settings are excluded for exactly this reason. Treat each row as a question to answer, not a decision already made.

Where the clicks go

Product areas ranked by total clicks. “Chat row context” is the auto-tracked layer inside an open conversation — reply, copy, AI compose, and so on.

Feature drill-down

Every tracked element, grouped by area and rolled up across contexts. Expand an area to see individual controls down to the smallest icon button.

Engagement per view (clicks ÷ times on screen)

How often an element gets clicked when it is actually visible. Sorted weakest first: low value + high exposure = users see it and pass it by.

How to read this. The figure is a ratio, not a percentage — 0.02 means two clicks per hundred views, 7.95 means the element is clicked about eight times per view (normal for list rows and composer controls, where one view absorbs many clicks). Persistent chrome (left nav, top bar) sits on screen for the whole session, so its denominator is inflated by design and it floors near zero — that is geometry, not disinterest. Compare within a group, never across. Only features emit a visibility event at all, so this is a subset of the product.

Feature co-adoption

Of the teams that use the left-hand feature, the share that also use the right-hand one. This is team-level co-adoption computed from the per-team click counts — it is not a click sequence.

Why this is not a step-by-step funnel. chatmary exposes a /ui-clicks/funnel endpoint, but it is returning impossible numbers and its results are order-blind — see Data quality below. Rather than dress up broken numbers as a user journey, this view uses the one relationship the aggregate can actually support.

Friction — rage clicks

Three or more rapid clicks on the same element: the user clicked, nothing happened, they clicked again. Ranked by rage rate among elements with at least 10 clicks.

Data quality

Problems found in the tracking pipeline while building this dashboard. These limit what the data above can honestly claim.

Funnel endpoint — evidence

Sessions reported by /ui-clicks/funnel versus total clicks recorded for the same element in the same window. A session containing an element cannot outnumber clicks on it.
